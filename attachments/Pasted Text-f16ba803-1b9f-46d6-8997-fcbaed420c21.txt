Goal
1. Admin Payments page shows ALL processor options as cards, even with empty credentials.
2. Admin can paste keys later, per processor, and hit Save.
3. Customer checkout lists the same options. Unconnected processors show as "Coming soon". Connected+Live processors become selectable. Cash / pay at pickup stay available.
4. Secrets never go to the browser. Public settings only store which processors are enabled, environment, publishable keys, and labels.

Processors to show (in this order):

A. Stripe — recommended first
   Rate: 2.9% + $0.30 online, Apple Pay + Google Pay included
   Fields: publishable key (pk_), secret key (sk_), webhook secret (whsec_), statement descriptor
   Methods: Card, Apple Pay, Google Pay, ACH (0.8% cap $5)
   Flow when live: authorize at checkout, capture when tablet Accepts, void if declined

B. Helcim — cheapest at volume
   Rate: interchange + 0.50% + $0.25 online, $0/mo
   Fields: account ID, API token, checkout token / HelcimPay.js token
   Methods: Card, Google Pay, ACH (0.5% cap $6)

C. Square — only if the shop already uses Square hardware
   Rate: Online API 2.9% + $0.30 (not the Free hosted 3.3% rate)
   Fields: application id, access token, location id
   Methods: Card, Apple Pay, Google Pay, cash app if Square enables it

D. Stax — high volume later
   Rate: $99/mo + interchange + $0.15–$0.18
   Fields: public key / web token, secret API key
   Default off. Label: "Turn on after \~$40k/month"

E. PayPal — optional, not primary
   Rate: \~2.99–3.49% + $0.49
   Fields: client id, secret
   Default off. Note: expensive on $25 pies

F. Cash / pay at pickup / pay on delivery
   Already exist. Always available. No keys.
